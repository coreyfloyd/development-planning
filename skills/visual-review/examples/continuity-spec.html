Why this exists

Before

  • Continuity tools are embedded in a personal configuration repository.
  • Paths and host assumptions prevent reuse.
  • Wrap-up calls private record, knowledge and persistence bindings.
  • Hooks work in only one coding tool.

After

  • A public Apache-2.0 continuity package with fresh history.
  • Installs in Claude Code and Codex with no configuration required.
  • Six hooks work in both tools; handoffs cross between them.
  • Optional profile bindings preserve an existing workflow.

Checklist spine and profile

Record, knowledge, persist and metadata are optional slots. Lessons uses harness improvement. An empty slot does not fail; its unfinished items become handoff open loops. The record check runs only when its slot is bound.

A profile can bind slots and add steps after steps 1–5; it cannot remove spine steps or add work after handoff. Cleanup of agents and merged worktrees, context health and next-work selection are profile additions, preserving the source workflow's nine-step order.

Release order

Probe all five hook moments live before any other work. Next introduce behavior-preserving seams, move once into a public repository, and verify the consumer across its supported machines in both tools. Applied findings and remaining limits

The source review applied one Fatal and five Significant findings: gate the record check on a bound slot, enumerate spine steps and slots, limit unattended wrap to user-launched interactive sessions, document five reversals of the earlier design, keep private reference terms outside the public repository, and include the checklist reminder hook.

Three source Minor findings remained: stale checks are silent for sessions that never wrote a handoff; pre-tag Codex installation is unstated; the default handoff location is unstated. Those source uncertainties are retained rather than silently resolved here.

Decisions

Q1 · Which checklist steps ship?

The current workflow has nine steps; the earlier note named five slots without placing cleanup, context health or next-work selection.

Recommend A: it keeps local workflow dependencies in the profile while preserving a short reusable spine.

Q2 · Which test seams belong in the first release?

Three seams already exist: hooks, resume and the consumer. Five new seams are install, release, personal-reference checking, the Codex probe and checklist profiles.

Recommend A because it gives every story a failing test, including profile immutability and retention on uninstall.

Q3 · Signed archives in the first version?

The source interview was interpreted as choosing a plugin, install script and signed archives; choosing an existing signing key supported that interpretation. This card makes the release decision explicit.

Recommend A for publisher verification and a consistent release contract.
